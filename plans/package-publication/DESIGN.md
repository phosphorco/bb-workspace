# Design: move bb-identity and bb-provider-settings to bb-community-plugins

Status: steward decision (Cole's executive grant, 2026-10-04). Plan: `../package-publication.plan.pkl`.

## 1. History-preserving transfer

Use `git subtree split --prefix=packages/<name>` in `plugins`, then
`git subtree add --prefix=packages/<name> <split> ` in `community-plugins`
(fetched from a local path, never pushed anywhere else). This carries
bb-identity's 21 commits and bb-provider-settings' 2 commits, rewritten to the
package root. `git-filter-repo` is not installed, and subtree is built into git.

- Record each split in `split-tips` as `<pkg> <split-tip> <plugins-source-sha>`,
one row per package. The oracle checks that the tip's tree equals
`source:packages/<pkg>`.

Run the split at the plugins commit that removed the private-consumer suites
  (step 3). That way the public history's tip has no private-plugin imports.
- The private-stage `standalone.sh` check skips manifests, since the fork SDK
  tarball devDependency is only replaced during the community adaptation. The
  public-stage check covers manifests too.
- Older commits in the public history still contain those suites, so they
  become public. They only exercise private plugin entry points through
  relative paths, and contain no secrets. **Check before pushing:** grep the
  split history for tokens, hostnames and `.bb/` paths. If anything sensitive
  shows up, **stop** and ask Cole for a decision (for example rewriting that
  file out of history, or accepting it). Never quietly fall back to a squash:
  the goal requires preserved history.

## 2. Layout and toolchain in community-plugins

- `workspaces: ["packages/*", "plugins/*"]`. The packages build first because
  npm runs workspaces in declaration order, and plugins consume `dist/`.
- **Bun stays the packages' own build and test runtime.** Each package adds the
  exact devDependency `"bun": "1.3.14"`. `npm run` puts `node_modules/.bin` on
  PATH, so local runs, `validate-pull-request.yml` and `publish.yml` need no
  setup-bun step. Rewriting `bun build` and `bun test` to Node equivalents
  would be a separate change with no user value.
- **Manifests are hand-owned in community** (community has no generator):
  - drop the "Generated by" marker;
  - resolve `catalog:` to the current exact plugins catalog values;
  - `repository`, `homepage` and `bugs` point at `phosphorco/bb-community-plugins`
    with `directory: packages/<name>`;
  - keep `publishConfig.access: public`;
  - versions stay `0.1.0`, with no API or `exports` change.
- **SDK:** the fork-tarball devDependency on `@get-bb/plugin-sdk` becomes the
  public npm `@get-bb/plugin-sdk@0.5.29`, the same version Perspectives uses.
  Peer ranges stay unchanged. **Probe first:** if a package's own
  typecheck or tests need fork-only SDK surface, that check moves to plugins
  with the consumer suites instead of shipping in the public package.
- **Fork-proof only, stays in plugins:**
  - bb-identity's `proof-sdk-check`, `tsconfig.proof-sdk.json` and
    `examples/local-proof` read `fork/build/proof-bb`;
  - `browser-check` needs Playwright with private fixtures.

  These move to plugins as `tools/package-consumers/bb-identity/` (see §3), or
  are retired if no plan still references them.
- `tsconfig.json` in each package extends `../../tsconfig.base.json` (community
  has an equivalent base). Settings that differ go into the package's own
  config.

## 3. Where private-consumer suites land (plugins)

- `plugins/tools/package-consumers/bb-provider-settings/` receives
  `test/integration/consumers/**`, `native-boundaries.test.ts`,
  `central/page.test.ts` (imports the private plugin-provider-settings app),
  recorded host receipts with absolute host paths (`test/integration/receipts/`),
  and any helper only they use.
- The oracle is `standalone.sh`. Witness: 83 code files reach outside the
  package tree today (77 in provider-settings `test/integration`, 1 in
  `test/unit`, 3 in the identity browser fixtures, plus both manifests' fork
  SDK tarball). Each one moves, or is rewritten to import the package by name.
- `plugins/tools/package-consumers/bb-identity/` receives
  `type-tests/browser/**` (the progress-inbox fixtures import thread-progress)
  and the fork-proof checks from §2.
- They import the package by name (`@phosphorco/<name>`), resolved through the
  workspace before cutover and through npm after.
- Root scripts change accordingly:
  - `identity:browser-check` and `identity:proof-sdk-check` point at the new
    location;
  - a new `packages:consumers-check` runs the provider-settings consumer suite.

  These suites are package-to-plugin integration evidence. They are not part of
  the default `bun run test` unless they already are today; I preserve the
  current wiring.

## 4. Publish workflow

Extend community `publish.yml`. Tag-driven releases already fail on an
existing version, so no version-skip step is needed:

- Add `bb-identity` and `bb-provider-settings` to the dispatch choices and the
  tag triggers `<name>/v*`.
- Map their workspaces to `@phosphorco/<name>`. A per-target source path
  (`packages/<name>` vs `plugins/<name>`) feeds the tag/source diff.
- Same steps as today: `npm ci`, test, typecheck, build, pack inspection,
  `npm publish --access public`, OIDC first and `NODE_AUTH_TOKEN` fallback.
- **Provenance:**
  - add `--provenance` for the two packages; the repo is public, so npm accepts it;
  - plugin releases keep their current command.

- Add a `dry_run` dispatch input that runs everything up to `npm publish`, then
  prints `dry run: <workspace>` instead of publishing. It is used to verify
  each package before the bootstrap.

`validate-pull-request.yml` also triggers on push to `main` (direct pushes
otherwise get no validation) and adds `npm pack --dry-run` for both packages.

**Bootstrap (Cole):**
1. Add a temporary `NPM_TOKEN` to bb-community-plugins, and push or approve
   the tags `bb-identity/v0.1.0` and `bb-provider-settings/v0.1.0`. The
   alternative is a local `npm publish` from a clean community checkout.
2. Configure each package's trusted publisher: `phosphorco` /
   `bb-community-plugins` / `publish.yml`.
3. Delete the token.

## 5. Consumer pin policy

- **plugins:** exact `"0.1.0"` for every consumer.
  - The generator (`tools/workspaces-sync/definition.ts`) drops both
    libraries, their tsconfig references, and their build, test and typecheck
    filters.
  - Consumer dependency specs become exact versions, then `sync:fix` and
    `bun install` regenerate everything.
- **community:** exact `"0.1.0"` (agentation-mentions, Perspectives). npm
  workspaces link the local package at a matching version, so shipped
  manifests stay registry-valid.
  - agentation-mentions drops its `sdk-artifacts` tarball.
  - Perspectives lands from the campaign hand-off: the seven files must be
    byte-identical to `HANDOFF.json`, and any adaptation is a separate commit.

## 6. References

- Update `.agents/skills/bb-identity/**`, workspace `AGENTS.md` (the shared
  packages sentence), and the plugins and community `AGENTS.md`/`README.md`
  package sections.
- `fork/scripts/verify-selected-kernel` reads workspace
  `plans/artifacts/bb-identity-kernel-*`, not package sources, so the fork is
  unchanged.
- Retire the `sdk-artifacts/phosphorco-bb-identity-*` tarballs only once
  `git grep` finds no consumer.

## 7. Cut-over order (every pushed commit green)

1. **plugins:** disable `publish-provider-settings.yml` (its own commit, pushed
   first; campaign guard).
2. **plugins:** relocate the private-consumer suites (§3). The package-edit
   freeze begins. Run plugins checks, then push.
3. **community:**
   - subtree-add both packages;
   - adapt manifests and tsconfig (§2);
   - point agentation-mentions at `0.1.0`;
   - land Perspectives;
   - update the lock;
   - run `npm ci`, test, typecheck, build and pack;
   - push.

   plugins is untouched and still green on its workspace copies.
4. **community:** extend `publish.yml` and validate (§4); push.
5. **Cole:** bootstrap the publish, then configure the trusted publishers.
6. **plugins:**
   - remove `packages/`;
   - make the generator and consumers exact `0.1.0`;
   - regenerate;
   - consumer suites resolve from npm;
   - run the full checks;
   - push.

   The freeze ends. plugins never depends on an unpublished version, because
   step 6 waits for `published.sh`.
7. Update references (§6), check CI, run the reconcile tail (full check,
   reload of changed plugins including the single Perspectives reload), promote.
8. Send closure to thr_qjduvhha3z: SHAs, the published integrities from the
   registry (`dist.integrity`), and the reload receipt.

## 8. Redesign (Cole, 2026-10-04): inverted consumer testing

This supersedes §3 and the relocation in §7 step 2. The contract is the accepted
`test-triage.md` in thread storage, including its binding Amendments R1–R4.

- **Packages:** each package keeps only tests of its own public behaviour and
  ships an additive `/testing` kit:
  - provider-settings: `./testing` and `./testing/react`;
  - identity: `createIdentityWireFake` and `defineStateStorageConformance`.
- **Plugins:** each consumer plugin owns kit-based tests in its own tree.
- **Removal:** the central registry and the private-plugin suites leave the
  packages in the same commit that adds their replacements.
- **Evidence archive:** goes in the **private** plugins repo at
  `evidence/package-publication/`, written by `archive.sh`. `bb-workspace` is
  public, so `plans/artifacts/` there would publish private plugin details and
  host paths.
  - The archive is byte-identical, checked against the original git blobs and
    disk files, and pushed before any removal.
  - Every removed file that isn't archived gets a row in
    `evidence/package-publication/DISPOSITION.md`: pruned, or replaced-by
    `<plugin test>`, with a rationale.
- **History:** the public repo's history is decided by Cole (`history-policy`
  selector), then this design and the move oracle are revised and re-reviewed.
